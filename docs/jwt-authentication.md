# HTTP JWT 검증과 저장소 역할

HTTP 인증 필터는 다음 순서로 처리합니다.

1. Redis blacklist에서 현재 access token의 폐기 여부를 확인합니다.
2. JWT의 서명·만료·`token_use=access`를 검증하면서 같은 파싱 결과의 `memberId`를 사용합니다.
3. PostgreSQL에서 회원이 탈퇴하지 않았는지 확인한 뒤 인증을 설정합니다.

blacklist 또는 회원 조회에 실패하면 503으로 인증을 거부합니다. 캐시 제거가 이 두 검사를 생략하는 것은 아닙니다. Refresh Token은 Redis의 비교·교체와 활성 회원 행 잠금으로 별도 처리합니다.

## claims 캐시를 제거한 이유

이전 필터는 캐시 조회 전에도 서명·용도·만료를 검증했습니다. 따라서 Redis에 같은 토큰의 `memberId`를 보관해도 필수 검증을 줄이지 못했고, 캐시 미스에서는 ID 조회와 TTL 계산을 위해 다시 파싱했습니다.

현재 HTTP 필터는 검증된 JWT를 한 번 파싱하고 그 결과를 사용합니다. `jwt:claims:*` 캐시의 조회·저장·빈을 제거했습니다. 기존 키는 원래 TTL로 만료되며 인증에 사용하지 않습니다. 별도 운영 Redis 삭제 작업은 필요하지 않습니다.

이 변경은 중복 파싱과 불필요한 캐시 I/O를 제거한 것입니다. 응답 시간이나 처리량 개선 수치를 측정한 결과는 아닙니다. 모집 목록 캐시, blacklist, Refresh Token, 알림 Pub/Sub의 Redis 사용은 유지합니다.
